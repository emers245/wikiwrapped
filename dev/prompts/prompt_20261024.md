# Wikipedia Wrapped: desktop-app readiness (prompt 1 of 2)

## Context

Wikipedia Wrapped (this repo) currently runs as a developer tool. It lives in a git checkout, runs in a conda env, is launched by `run.sh` from a terminal, and is configured through the interactive CLI `scripts/setup_takeout.py`. The goal is to turn it into an installable Mac and Windows app that people without technical experience can use. It is a free passion project, so no paid services of any kind.

Packaging is handled in a **separate, later prompt**: conda `constructor` installers, a bundled MiniLM model, hosting for the reference space, desktop shortcuts, and CI. This prompt covers only the application changes that packaging depends on. All of them have to work in the normal dev checkout too.

Before planning, read `repo_spec.md`, `README.md`, `config.py`, `app/localconfig.py`, `app/sync.py`, `app/drive.py`, `app/api.py`, `scripts/setup_takeout.py`, `run.sh` and `app/static/`. Existing design decisions (D-numbers in repo_spec) still hold unless this prompt changes them explicitly.

## Decisions already made (do not reopen)

1. **Takeout via a watched folder is the default path.** The user picks one or more local folders, and each sync scans them for Takeout zips. The zips get there either by hand (the user downloads them) or through Google Drive for desktop, which mirrors the Drive folder where Takeout delivers. No Google sign-in or Cloud project is needed.
2. **The existing OAuth/Drive path stays as an "Advanced" option.** Its behavior doesn't change and it still uses the user's own client secret. It must stay lazily imported and fully optional.
3. **pywebview is the app window.** It replaces opening a browser tab, provides native folder and file pickers, and quits the app when the window closes.
4. **Wikimedia User-Agent identifies the project, not the user:** `WikipediaWrapped/<version> (https://github.com/emers245/wikipedia-wrapped)`. A personal contact email is no longer required. An optional override (env var or setting) is fine.
5. **User data moves out of the program folder**, into the standard per-user location. The program folder must be treated as read-only at runtime.

### Milestone 2: Watched-folder Takeout source

- During sync, scan each folder recursively, to a sensible depth, for Takeout zips using the existing name pattern. Then:
  - Reuse `extract_history.load_takeout_zip`, the visit log, dedup and the processed-archives table. Don't build a parallel pipeline.
  - Track idempotency with a key that suits local files, such as resolved path + size + mtime. Explain the choice. A zip already ingested through Drive, or under another path, must not create duplicate visits; the existing dedup should cover this, so confirm it does.

- Tests: a new zip, an unchanged zip (skipped), a modified zip, a duplicate copy in a second folder, a non-Takeout zip, a corrupt zip, and a missing folder.
